=N ↵精确设置 N，固件钳位 16–6000，回 EV N=<值>=1500\n
无需回车：上表中除 =N 之外的各行都是单字符命令，按下即执行。
=N 是行命令：必须以 \n（换行 0x0A）结束，例如发送 =1500\n → 固件回 EV N=1500（超出 16–6000 只钳不拒）。
AdDemo 与 FinalDemo 的区别：AdDemo 没有任何 CPU 像素渲染 —— 屏幕上的每一个像素（含 y<16 那一条信息条的字形）都由加速器的 FILL/COPY/ALPHA/KEY 指令写出来；CPU 只做"组命令流 + 调度清屏引擎 + 帧边界发布 + 串口/UI"。
信息条读数（屏上 y<16 那条，全部由引擎画的）：FPS= 已发布帧率（翻转被扫描输出确认生效的次数/秒）· N= 每帧精灵数 · SZ= 精灵边长 · MPX= 等效像素吞吐 = N*SZ*SZ*FPS/1e6 · B= 引擎占用率（主循环采样 BLT_STATUS 得到）· 场景名 · A= 主 alpha · 标记 FR(按帧推进) F(LUT 特效) X(scissor) Y(属性侧口) Q(自动爬坡)。最坏串 61 字符 = 488px，黑底铺到 584px，右标签从 904px 起，互不重叠。
成本行：固件每秒最多打一行 EV cmd path done: n=… cycles=… cyc/sprite=…（本趟起点 → 引擎空闲的墙钟 core 拍数），与 FinalDemo 同口径同格式。
属性侧口协议（固件侧纪律）：每个精灵先写 ATTR_PORT(0x8C) 一个 32bit 属性字，再写命令的 8 个字；引擎每条命令弹一个属性字，所以要么每条命令都写、要么一条都不写（混合写必然错位）。FIFO 为空 = 默认 blend 0 / RGB565 / global_alpha 255（等价字 0x00003FC0）。位域：[3:0] 混合模式（0 默认 / 1 alpha / 2 加算 / 3 乘）、[5:4] 源格式（0 RGB565 / 1 ARGB1555 / 2 ARGB4444）、[13:6] global_alpha（255=无）、[31:24] flags（bit0 跳过 alpha 测试 / bit1 强制不透明）。
需要下一版 bitstream：scissor(0x90~0xA0)、扫描输出 LUT(0xA4~0xB0)、属性侧口(0x8C) 都是本次冻结接口新增的寄存器。开机时固件会写回读校验它们：读不回来就打印 feat WARN: … 并自动降级（辉光退回 RGB565 普通混合、裁剪与 LUT 特效停用），演示不会因为"新 RTL 还没 P&R"而挂掉。
回包：开机打印一次启动横幅（含地址表、按键表、属性字默认值、信息条最坏宽度自检）；命令被接受时打印 EV …（如 EV scene=0 (GLOW)、EV N=1500、EV size=64、EV scissor=0、EV attr=0）。
波特率：固件按 BSP 自行设定（默认 115200 8N1）。日志出现乱码说明波特率不匹配，改回 115200 重连。
