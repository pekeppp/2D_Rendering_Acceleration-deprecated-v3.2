## 1. 系统与 RTL 架构

### 1.1 系统数据流

```
 RISC-V(Sapphire)                     FPGA (Ti60F225)
   │  APB slave0 @0xF8100000
   │  (efx_apb3_2_axi4_lite 桥)
   ▼
 ┌──────────────────────────┐   AXI4 主机(读/写,128bit)   ┌──────────────┐
 │ blt_top（2D 加速器）      │────────────────────────────▶│ AXI 互联      │
 │  blt_regs_axi_lite 0x00~0xB0                          │ (3主→1从,128b)│
 │  cmd_fifo (2048×32b)     │                             └──┬───▲───────┘
 │  dl_fetch（DFU 取指器）   │◀── desc 读(rd_sel=2'b10) ──────┘   │
 │  blt_engine_fsm          │                                    │
 │   ├ blt_addr_gen         │                                    ▼
 │   ├ axi_rd_master ×1     │   fg/bg/desc 三流共享          ┌──────────────┐
 │   ├ axi_wr_master ×1     │                                │ DDR3 硬核     │
 │   ├ src_fifo/bg_fifo/wd_fifo                              │ (MT41J128M16,│
 │   └ pixel_path（2 lane）  │                                │  256MB,16bit)│
 └──────────────────────────┘                                └──────▲───────┘
 ┌──────────────────────────┐   AXI4 读                      │
 │ scanout（fb_scanout）     │────────────────────────────────┘
 │  vga_timing @37.36MHz    │── RGB565 →（3×2×256 LUT）──▶ HDMI TX ──▶ 显示器
 │  line_fifo（异步 ≥2 行）  │
 └──────────────────────────┘
 ┌──────────────────────────┐
 │ clr_engine（并发清屏）    │── AXI 写（与引擎共享写仲裁器）
 └──────────────────────────┘
```

关键结构事实：
- **引擎只有一个 AXI4 读主机、一个 AXI4 写主机**（数据宽度 **128 bit = 16 B = 8 个 RGB565 像素**，小端，低地址像素在低 lane：`lane0 = px0`）。
- 读通道由 **fg（源）/ bg（背景）/ desc（显示列表）三流共用**；写通道由 **BitBlt 引擎 / 清屏引擎 / CPU 三流共用**（2 级仲裁）。
- **扫描输出是独立外设**，不占引擎寄存器窗口的写口，但**共享 DDR 读带宽**。

### 1.2 模块清单（`rtl/`）

| 文件 | 职责 |
|---|---|
| `blt_top.v` | 引擎顶层：例化 regs + fifo + engine + DFU；只连 AXI 口 |
| `blt_regs_axi_lite.v` | AXI-Lite 从机 + **全部寄存器（0x00~0xB0）** + 属性 FIFO(深16 FWFT) + cmd_fifo 写口仲裁 |
| `cmd_fifo.v` | 指令 FIFO：**256 条 × 8 字 = 2048×32bit**（BRAM）；`cmd_count = word_count>>3` |
| `dl_fetch.v` | **DFU 取指器**：读 16B 描述符 → 查几何表（16 条直接映射 cache）→ 展开成 8 字命令 → 推 cmd_fifo |
| `blt_engine_fsm.v` | 主控 FSM：`IDLE→POP(8字)→DEC→EXEC(行流水)→WDWAIT`；行窗口/掩码/scissor/属性锁存 |
| `blt_addr_gen.v` | 纯组合：行首地址、`px_skip`、`cover_beats`、16B 段式覆盖突发拆分 |
| `axi_rd_master.v` | AXI4 读主机：INCR、ARSIZE=3'd4、**最多 4 笔在飞**（OUTSTAND=4）、信用握手、三流仲裁 |
| `axi_wr_master.v` | AXI4 写主机：相邻词合并 INCR 突发（**≤16 拍**）、WSTRB 逐拍、`b_pending` 单笔在飞、`cmd_end_flush` 尾冲刷 |
| `stream_reader.v` | 128bit↔16bit 流式读取（双词槽预取，2 px/拍） |
| `pixel_path.v` | 像素通路：COPY 直通 / FILL 常量 / KEY 比较 / ALPHA 混合 / 属性混合（双 lane 各一套） |
| `sync_fifo.v` | 参数化同步 FIFO（BRAM 可推断形式） |
| `clr_engine.v` | 并发清屏引擎（与显示缓冲/正在画的缓冲做硬件互斥） |
| `ARC_2DRA/rtl/video/fb_scanout.v` | 扫描输出 + FLIP + 颜色 LUT（读口在 pixel_clk 域） |
| `ARC_2DRA/rtl/video/axi_rd_arb.v` / `axi_wr_arb.v` | DDR 侧读/写两选一仲裁 |
| `ARC_2DRA/rtl/blt/blt_apb_top.v` | APB → AXI-Lite 桥接顶层 |

### 1.3 引擎流水线与逐命令生命周期

```
ST_IDLE ──(cmd_wcount≥8 && go)──▶ ST_POP (弹 8 字: w0..w7)
        ──▶ ST_DEC  锁存 cur_op/cur_W/cur_H/cur_alpha/cur_key/cur_mask/cur_msk_on
                     ★S5：同时弹 1 个属性字（attr_pop，空则不弹）、锁存 scissor
        ──▶ ST_EXEC 行流水：
              RS_INIT  算 4 个行带窗口（掩码用）+ 起点
              RS_LOOP  发第 r+1 行突发 ‖ 算第 r 行（**行级重叠**）
                       ├ fg 突发（COPY/KEY/ALPHA）→ src_fifo
                       ├ bg 突发（ALPHA 或属性混合）→ bg_fifo
                       └ 像素通路逐像素处理 → wd_fifo → 写突发
              RS_DRAIN 行尾残词 drain ∈ {0,1}
        ──▶ ST_WDWAIT 等 wr_commit_idle（wd 真空 + 写主机空闲 + 无未回 B）
        ──▶ ST_IDLE（DONE=1）
```

要点（都对应已实测的 bug 修复，改代码时别回退）：
1. **行是独立事务单元**：每行一组读/写突发，突发绝不跨行 ⇒ 天然不越 4KB、天然行距正确。
2. **行级重叠**：发第 r+1 行突发发生在算第 r 行期间，DDR 读延迟被运算盖住；`issue_r ≤ proc_r+1` 保证 FIFO 内最多 2 行 → **FG/BG FIFO 深度须 ≥ 2×cover_beats(max)**，960 宽时 = 2×121 = 242 → 取 **256**。
3. **精确 drain**：`弹词数 = (px_skip + W)/8`，`cover_beats = ceil((px_skip+W)/8)` ⇒ drain ∈ {0,1}。"drain 到 FIFO 空"是错的（会把预取的下一行数据丢掉）。
4. **指令边界写屏障**（S1/v2.10 定型）：`ST_WDWAIT` 出口判据是 `wd_empty && !wd_busy && wr_commit_idle`，`wr_commit_idle = wr_idle_committed && wd_count==0 && !wd_busy`，`wr_idle_committed = (b_pending==0) && (wr_master.st==S_IDLE)`。**这保证 DONE=1 时像素真的落进 DDR（B 已回）**，不是"看起来不忙"。软件可以放心把 DONE 当"可以改这块内存"的判据。
5. `blt_idle_st()` 的正确读法（固件实践）：`(STATUS & DONE) && (STATUS & FIFO_EMPTY) && !(STATUS & ERR)`。

### 1.4 FIFO 清单（类型 / 位宽 / 深度）

| FIFO | 位宽 | 深度 | 时钟域 | 用途 |
|---|---|---|---|---|
| `cmd_fifo` | 32 | **2048 字 = 256 条命令** | core | 指令排队；GO 后自动消费，可边推边跑 |
| `src_fifo`（fg） | 128 | **256** | core | 源像素突发回程；容纳 2 行（960 宽 = 121 词/行） |
| `bg_fifo` | 128 | **256** | core | ALPHA / 属性混合的背景读回程 |
| `wd_fifo` | **176**（128 数据 + 16 WSTRB + 32 地址） | **16** | core | 待写词；攒够才发 W，供写合并 |
| desc FIFO（DFU 内） | 128 | 16 条 × 16B | core | 描述符预取缓冲（2 个块 + 抖动余量） |
| 几何表 cache | 128 | 16 条直接映射（索引 `spr_id[3:0]`，标签 `spr_id[15:4]`） | core | atlas 几何常驻 |
| **属性 FIFO** | 32 | **16（FWFT，软复位清空）** | core | 每命令 1 个属性字，按序配对 |
| `line_fifo`（scanout） | 16 | 2048（≥2 行，一行 960 entries） | **异步** core→pixel | 唯一跨时钟域通道 |

### 1.5 突发行为（AXI4）

读（AR/R）：
- `ARBURST=INCR(2'b01)`、`ARSIZE=3'd4`（128bit 口 ⇒ 16 B/拍）、`ARLEN=拍数−1`。
- **最多 4 笔在飞**（OUTSTAND=4）；`rready` 由队头目标 FIFO 可收性门控（反压）。
- 读**没有 WSTRB** ⇒ 用"覆盖式对齐读"：从 16B 对齐起点整拍读，多读的 padding 像素在像素通路丢弃。

写（AW/W/B）：
- 相邻写词**合并成一笔 INCR 突发，最大 16 拍 = 256 B**（也做 4KB 跨页检查）。
- `WSTRB` 逐拍直通：头/尾半拍只置需要的字节，"**宁可少写不可多写**"（矩形外一个字节都不许动）。
- **B 响应串行**：一笔写完成才收下一笔；`b_pending` 门控下一笔 AW。ALPHA 要读同一行的背景时**必须等 B**（写后读危险）。
- 段式拆分（`blt_addr_gen`）：`head_bytes = 16 − (A mod 16)`、`tail_bytes = (A+L) mod 16`；`head/mid/tail` 三段，行宽 ≤8 像素时退化为单拍掩码事务，**禁止负拍数**。
- 实测：整屏 960×540 FILL `AW=4050 = ⌈64800/16⌉`（理论下限）、`burst_max=16`、`burst_avg=16.000000`、写主机 AXI 侧 **1.13 拍/16B 词**（≈14.2 B/拍 ≈1.42 GB/s）。

### 1.6 时钟域

| 时钟 | 频率 | 用的地方 |
|---|---|---|
| **core_clk** | **100 MHz** | CPU、AXI 互联、blt_top 全部、DFU、清屏引擎、DDR 控制器 AXI 侧 |
| **pixel_clk** | **37.3632 MHz** | vga_timing、line_fifo 读侧、HDMI TX |
| ddr 物理时钟 | 400 MHz（DDR 800 Mbps） | DDR3 硬核内部（RTL 不直接碰） |
| TMDS 线速率 | 373.6 Mbps/线 | HDMI 串行输出 |

- **跨时钟域只有一个通道：line_fifo（异步）**；引擎内部全单时钟域，禁止裸打一拍。
- FLIP 的 `fb_cur_sel`、LUT 的 bank/使能都用帧边界锁存 + 格雷码回同步（core↔pixel）。
- 复位：统一异步复位 / 同步释放，core 域与 pixel 域各自复位。

### 1.7 仲裁器（三层）

写通道（DDR 侧，`axi_wr_arb`，2 选 1）：
- 参与方：**BitBlt 写主机** vs **清屏引擎/CPU 写**。
- 规则：AW 受理与转发解耦（skid buffer）——**"让位那一拍的 AW 握手"曾被漏记在飞计数，导致 B 错路 → BUSY 永不落**（§12 的真 bug，已修）。修好后引擎与清屏可并发。
- **清屏引擎的硬件互斥**：目标缓冲 == `fb_cur_sel`（正在显示）或 == `DRAW_SEL`（引擎正在画）⇒ 拒绝写、置 sticky ERR；运行中被抢则把已组好的那一笔按规范发完（≤16 拍）再停。

读通道（DDR 侧，两级级联 `axi_rd_arb`）：
```
CPU ──c_─┐
         ├─ u_rd_arb_l1 ──c_─┐
BitBlt ──s_─┘                ├─ u_axi_rd_arb ──▶ DDR 控制器读口
            扫描输出 ──s_─────┘
```
- L1：CPU vs BitBlt（BitBlt 是 `s_` 侧，`s_hold=0`；L1 的归还判据是 `s_quiet`）。
- L2：L1 汇合流（`c_`）vs **扫描输出（`s_`，有硬死线）**；扫描输出整行取数期间用 `s_hold` 钳住，`WAIT_MAX=32`/`LEAK_TO=256` 有界兜底。
- **优先级：扫描输出 > CPU/BitBlt**。
- `axi_rd_master` 内部（引擎侧三流）：**fg > bg > desc**；任何一路等待超 `AGE_MAX=64` 拍则提权一笔（防饿死）。
- 实测（`tb_dl_arb`，五路并发 40000 拍）：desc 最长等待**恰为 64 拍**（提权生效）、扫描输出 31 拍、fg 73 / bg 194 拍；引擎把 AR 队列压满时 **CPU 要等整段**（实测 39998 拍，引擎一停立刻放行 98 笔）。
- **板级已知缺陷**：ALPHA/KEY 场景里 desc 取指**偶发被饿过 `DL_TIMEOUT`**（看门狗在随机序号触发、`stall_seen=1`），即使超时值提到 65535 拍仍会触发。⇒ **显示列表路径在读密集场景不可靠**（写新 demo 时优先用逐条下发路径，见 §8.6）。

### 1.8 扫描输出（独立外设）

- 时序：**960×540@60**，像素时钟 37.3632MHz；水平 960/+48/+32/+80 → **1120**（+HSYNC）；垂直 540/+3/+5/+8 → **556**（−VSYNC）。
- `vga_timing.v` 参数化（`H_ACTIVE/H_FP/H_SYNC/H_BP`、`V_*`），1080p 只换参数（2200×1125 @148.5MHz）。
- 行预取：提前 1~2 行发 AXI 突发读（一行 1920B = 120 拍 @16B）→ line_fifo（异步 16bit×2048，≥2 行）→ 像素节奏输出。
- **FLIP**：`FB_SEL 0x24`（请求）→ 扫描输出在**下一个帧边界（垂直消隐起点）**锁存 → `FB_STAT 0x28` 的 `fb_cur_sel` 生效。⇒ 绝不会"一场里混两个缓冲"。
- **颜色 LUT**：3 通道 × 2 bank × 256 项 8bit→8bit，插在行缓冲之后、输出级之前（**不加流水级、不产生 1 像素相位偏移**，恒等表逐位无损）。表值**量化回 5/6/5 再位复制**。
- **帧脉冲**：每个帧边界 1 个 core 拍 → `IRQ_STATUS[1]=FRAME`（W1C）/ `IRQ_EN[1]`。`0x28[31:16]` 是场计数 `frame_cnt`（@60Hz 约 1092 s 回绕）。
- 健康度：`0x20 SCAN_DBG`：`[15:0]` = 欠载行数（正常恒 0）、`[31:16]` = 取数看门狗中止次数。

### 1.9 并发清屏引擎（0x2C~0x48）

- 一条命令 = FILL 一个矩形到指定缓冲：`CLR_ADDR/STRIDE/WH/COLOR` + `CLR_CTRL.GO`。
- `CLR_CTRL`：bit0=GO（1 拍脉冲）、`[3:2]`=目标缓冲号、bit4=ERR_CLR（清 sticky）。
- `CLR_STAT`：bit0=BUSY、bit1=目标缓冲已清、`[5:2]`=**四块缓冲的 clean 位图**、bit6=ERR（sticky）、`[31:16]`=上次 clear 的 AW 突发数。
- `0x48 CLR_CYC` = 上次 clear 的 core 周期数；`0x44 DRAW_SEL` = "引擎正在画哪块"，**写它会把该缓冲 clean 位清零**。
- 软件协议（FinalDemo/AdDemo 已实现）：一趟开画前 ①等清屏空闲 ②读 clean 位 ③**在 ② 之后**写 `DRAW_SEL` ④clean=0 ⇒ 退回命令式整片 FILL（宁多花 568k 拍也不在脏底上作画）⑤给清屏引擎下一条命令去清**第三块**。

## 2. 完整寄存器映射（0x00 ~ 0xB0）

### 2.1 地址空间

| 项 | 值 | 说明 |
|---|---|---|
| `BLT_BASE` | **0xF8100000** | APB slave0 窗口（CPU 视角）；**以生成 soc.h 为准** |
| 寄存器窗口宽度 | 12 bit（`ADDR_W=12`） | 0x000~0xFFF |
| `DDR_BASE` | **0x00001000** | `SYSTEM_DDR_BMB` |
| 帧缓冲 | FB0 = DDR_BASE+0x00300000；FB1 = +0x00500000；FB2 = +0x00700000 | 每张 0xFD200 B（960×540×2），间隔 1MB |

### 2.6 S5（v3.2）：属性侧口 / scissor / 扫描输出 LUT（0x8C ~ 0xB0）

> 这 9 个寄存器**全部是新增**；0x00~0x88 一位没动、没有任何重编号。

| 偏移 | 名称 | R/W | 位域与语义 |
|---|---|---|---|
| **0x8C** | `ATTR_PORT` | W | **属性侧口**。每写 1 次 = 往**属性 FIFO（深 16，FWFT）**压入 1 个 32bit 属性字；引擎在**每条命令起始**（`ST_DEC`，8 个命令字弹完之后）按序弹 1 个 ⇒ **必须"先写属性、再写命令"**。<br>FIFO **空**时引擎用默认字（**0x0000_3FC0** = blend 0 / RGB565 / ga 255 / flags 0）且**不弹**（弹脉冲只在非空时拉高）⇒ 不写属性的软件行为与旧版逐位相同。<br>位域：`[3:0]` blend_mode（0=按算子默认，1=alpha 混合，2=加算饱和，3=乘法，4~15 保留→按 0）<br>`[5:4]` src_format（0=RGB565，1=ARGB1555，2=ARGB4444，3 保留→按 0）<br>`[13:6]` global_alpha（**255 = 不淡**）<br>`[15:14]`、`[23:16]` 保留（键色仍走命令字 `w7`）<br>`[31:24]` flags：**bit0 = alpha 测试**（有效 alpha=0 的像素不写），**bit1 = 强制不透明**（按 255 算）<br>**写入不看 WSTRB**（整字入队，与 0x08 同口径）<br>★ **只写、读不回**（无法探测存在性） |
| **0x90** | `CLIP_X0` | RW | scissor 左边界（**含**） |
| **0x94** | `CLIP_X1` | RW | scissor 右边界（**不含**）⇒ 命中条件 `X0 ≤ x < X1` |
| **0x98** | `CLIP_Y0` | RW | 上边界（含） |
| **0x9C** | `CLIP_Y1` | RW | 下边界（**不含**）；区间**半开** `[x0,x1) × [y0,y1)` |
| **0xA0** | `CLIP_CTRL` | RW | bit0 = **ENABLE**（复位 **0** ⇒ 逐位回到旧行为；**可回读**）。<br>★ 坐标是**本条命令目的矩形的局部坐标**（原点 = 该行 `dst_base + row*stride` 的第一个像素、第 0 行 = 第一行）。全屏目的矩形时局部坐标 == 屏幕坐标。<br>启用后：矩形外的像素不写，整行在矩形外的行**不取数、不算**直接跳过。<br>★ 引擎在**命令起始**锁存本组寄存器（+属性字）⇒ 命令中途改不会撕裂本命令 |
| **0xA4** | `LUT_ADDR` | RW | `[9:8]` = 通道（**两位**：0=R 1=G 2=B，3 保留→该次写忽略）；`[7:0]` = 表内下标。★ 老写法"[8]=通道"只能编出 0/1 ⇒ **蓝色永远寻不到** |
| **0xA8** | `LUT_DATA` | W | `[7:0]` = 写入当前下标/当前 bank 的输出值（**写它就产生 1 拍写脉冲**） |
| **0xAC** | `LUT_CTRL` | RW | bit0 = **ENABLE**（请求，**立即**生效）<br>bit1 = **BANK**（`LUT_DATA` 写进哪个 bank）。★ **显示读的是"帧边界锁存的 bit1 的反相"** ⇒ 写口与显示口永远指向不同 bank，写表在物理上碰不到正在显示的表。bit1/bit0 都只在**帧边界**被锁存成"显示用的值"⇒ 一场之内只读一个 bank |
| **0xB0** | `LUT_STAT` | R | bit0 = **正在显示**的 bank（= 帧边界锁存值的反相） |

**LUT 正确发布序列（RTL 实测语义，与早期规格差一个反相！）**：
```
① 读 0xB0 → D = 现在显示的 bank
② 0xAC bit1 = ~D         （新表整张写进"非显示"bank）
③ 写 3×256 项：0xA4 = (ch<<8)|idx，0xA8 = 值
④ 0xAC bit1 = D          （= 写表之前正在显示的那个 bank）
   ⇒ 帧边界锁存后 显示 = ~D = 刚写好的那张表
```
早期规格写的"bit1 = 刚写的 bank"会让显示 bank 永远不动（表写进去一辈子不上屏，症状：信息条糊、fade 完全不生效、白闪洗不掉）。AdDemo 还做了 `lut_bank_calib` 开机标定，把极性打到 `EV lut polarity` 行。

### 2.7 读写语义要点（写驱动前务必记住）

1. `0x4C/0x50/0x54/0x68/0x6C/0x70/0x74/0x78/0x84/0x88` 只在 `DL_STATUS.BUSY=0` 时被 DFU 采样；**BUSY=1 期间写入被"静默忽略"（读回仍是旧值）**——不报错。软件必须先 `ABORT` 或等 `DONE`。历史上 `7bdd307` 那个"GEOM_MAX 被丢"的坑就是这么来的。
2. `DL_ERR` 是 W1C；写 1 清对应位；全清 0 且 `DL_STATUS.ERR` 的锁存随之清（`ERR = |DL_ERR`）。
3. `GO` / `ABORT` / `CLR_CTRL.GO` / `CLR_CTRL.ERR_CLR` 都是"写 1 产生 1 拍脉冲"，写 0 无副作用。
4. 写寄存器按 `WSTRB` 字节更新（驱动是 32 位整字写，全使能）；但 `0x08` 与 `0x8C` **整字入队、不看 WSTRB**。
5. `CTRL.SOFT_RST` 会清空属性 FIFO——一旦开始用属性侧口，软复位后必须重新开始"每命令 1 属性"的配对。

## 3. 命令编码：一条命令 = 8 × 32bit

### 3.1 精确位域（`blt_cmd_t`，32B，`_Static_assert` 锁定）

```c
typedef struct {              /* 小端，32 字节 = 8 个字 = 连续 8 次写 0x08 */
    uint32_t w0;   /* op + 掩码 */
    uint32_t w1;   /* src  */
    uint32_t w2;   /* dst  */
    uint32_t w3;   /* src_stride */
    uint32_t w4;   /* dst_stride */
    uint32_t w5;   /* W | H<<16   */
    uint32_t w6;   /* alpha */
    uint32_t w7;   /* color / key */
} blt_cmd_t;
```

| 字 | 位 | 字段 | 语义 |
|---|---|---|---|
| **w0** | `[1:0]` | `op` | **0=COPY（BLOCK_COPY）1=FILL（SOLID_FILL）2=ALPHA（ALPHA_BLEND）3=KEY（COLOR_KEY）**；>3 ⇒ `STATUS.ERR` + 跳过本条 |
| | `[2]` | `MASK_EN` | ★S3：透明块掩码生效位（CPU 写 0 = 旧行为） |
| | `[15:3]` | — | 未用（写 0） |
| | `[31:16]` | `MASK[15:0]` | ★S3：**4×4 块透明位图**（bit=1 表示"该块不透明/要画"；写 0 全透明）。仅 `OP=KEY && W≥4 && H≥4` 生效 |
| **w1** | `[31:0]` | `src_addr` | 源**字节**地址（FILL 忽略，写 0）。**建议 16B 对齐** |
| **w2** | `[31:0]` | `dst_addr` | 目的**字节**地址（任意字节地址均可，16B 内偏移由 WSTRB 处理） |
| **w3** | `[31:0]` | `src_stride` | 源**字节**行距（FILL 忽略）。通常 = 源图宽×2（图集内 stride 可大于精灵宽） |
| **w4** | `[31:0]` | `dst_stride` | 目的**字节**行距（屏 = 1920 = 0x780） |
| **w5** | `[15:0]` | `W` | 宽（像素） |
| | `[31:16]` | `H` | 高（像素） |
| **w6** | `[7:0]` | `alpha` | **0~255**（255 = 不透明），**仅 `OP=ALPHA`（或属性混合）用**；其余 op 写 0xFF 无害 |
| | `[31:8]` | — | 未用 |
| **w7** | `[15:0]` | `color` / `key` | `OP=FILL` ⇒ **填充色 RGB565**；`OP=KEY` ⇒ **键色 RGB565**；其余忽略（写 0） |
| | `[31:16]` | — | 未用 |

### 3.2 灰度区分：哪些是"命令字"、哪些是"寄存器"

- **命令字进 0x08（CMD FIFO）**，8 字一条；**属性字进 0x8C（属性 FIFO）**，每命令 1 个，**写在命令 8 字之前**。
- **掩码走命令字 `w0[31:16]` + `w0[2]`**（描述符路径由 DFU 从 `dw3[15:0]`/`FLAGS[7]` 搬来）；**不走属性 FIFO**。
- 键色**不是固定品红**：`w7[15:0]` 每条命令可编程；**0xF81F（洋红）只是软件/图集约定**（`KEY_COLOR`，图集透明处填它）。

### 3.3 一条命令的语义（各 op 数据流）

| op | 读源 | 读背景 | 处理 | 写目的 |
|---|---|---|---|---|
| 0 COPY | fg 突发 → src_fifo | 无 | 直通 | wd_fifo → 写突发 |
| 1 FILL | **不读** | 无 | 常量 `w7` 复制 W×H 次 | 同上 |
| 2 ALPHA | fg 突发 | **读目的原值**（bg 突发） | `(fg·A + bg·(255−A) + 127) >> 8`，三通道 | 同上 |
| 3 KEY | fg 突发 | 无 | `fg == w7[15:0] ? 丢弃 : 通过`（逐像素 keep） | 同上（带 WSTRB 掩码，全键色词**不提交**） |

- **ALPHA 是三腿事务**（读 fg + 读 bg + 写 dst）⇒ 每像素 **6 B DDR 流量**（RGB565）。
- KEY 跳过时**不写 DDR**；整词全键色时"只进位 jw、不提交"（省一笔写）。
- **COPY/KEY 不做重叠检测**：驱动约定不产生重叠指令（重叠需反向拷贝，v1 未实现）。

### 3.4 CPU 下发（按条）与硬件下发（显示列表）的关系

```
CPU 路径：  CPU ──9 次 AXI-Lite 事务/精灵──▶ cmd_fifo ──▶ 引擎
            （1 读 CMD_FIFO_COUNT + 8 写 CMD_FIFO_DATA），约 50~200 拍/精灵，且与引擎抢 FIFO 写口

列表路径：  DDR 描述符表 ──16B/条──▶ DFU 展开成同样的 8 字 ──▶ cmd_fifo ──▶ 引擎（FSM 一行不改）
            软件每帧只 3~4 次 MMIO
```
- 两条路径**字节级等价**（`tb_dl_basic` / `tb_dl_demo` 逐字节 0 mismatch）。
- 写口仲裁：**整条命令粒度互斥**——DFU 从第 1 字到第 8 字一直举着 `dl_cmd_req`，这段时间 CPU 侧 `awready/wready` 被压低（AXI 层反压，不是静默丢弃）；CPU 正写到一条命令中间时 DFU 让路。⇒ FIFO 里的字序永远"整条整条"，8 字对齐永不错位。
- `AUTO_GO=1`（默认）时 DFU 推入第一条命令后自动置 `CTRL.GO`，软件只需写一次 `DL_CTRL.GO`。

## 4. 属性字编码（S5，逐精灵 alpha / 可编程混合）

```
attr = (blend & 0xF) << 0
     | (fmt   & 0x3) << 4
     | (ga    & 0xFF) << 6
     | (flags & 0x3) << 24
ATTR_DEFAULT = attr(blend=0, fmt=0, ga=255, flags=0) = 0x0000_3FC0
```

| 字段 | 位 | 取值 |
|---|---|---|
| `blend_mode` | `[3:0]` | 0 = **按算子默认**（= 旧行为，整字惰性）；1 = **alpha 混合**；2 = **加算饱和**；3 = **乘法**；4~15 保留→按 0 |
| `src_format` | `[5:4]` | 0 = RGB565；1 = ARGB1555（字段位置与 565 相同，只有 bit15 是 A）；2 = **ARGB4444（A4R4G4B4）**；3 保留→按 0 |
| `global_alpha` | `[13:6]` | 0~255，**255 = 不淡** |
| `flags` | `[31:24]` | bit0 = alpha 测试（有效 alpha=0 的像素不写，**与 blend_mode 无关**，所以"硬抠图"也能用）；bit1 = 强制不透明（按 255 算） |

**混合数学（RTL 逐字）**：
```
A = floor(sprite_alpha · global_alpha / 255)     force_opaque ⇒ A = 255
alpha 混合: out = (fg·A + bg·(255−A) + 127) >> 8        ← 与 §11 金标准同一句
加算:       out = min(255, floor(fg·A/255) + bg)        （÷255 用 (x + (x>>8) + 1)>>8）
乘法:       out = (fg·bg) >> 8
统一量化回 5/6/5: {r8[7:3], g8[7:2], b8[7:3]}
```
- `blend=0 && op=ALPHA` ⇒ 退化成 `(fg·alpha + bg·(255−alpha) + 127)>>8`，**逐位等于旧版**（"兼容"是结构性的，不是旁路）。
- `blend=0` 时其余 op 走老 `case(op)` 分支。
- **ARGB4444 抽头是 A[15:12] R[11:8] G[7:4] B[3:0]**，4bit **位复制**成 8bit（`a4=8 ⇒ a8=136`）。**不能**沿用 RGB565 的 5/6/5 抽头（会把"红"拼成假字段、颜色整片错位）。
- **逐像素 alpha 只有 4 bit（ARGB4444）或 1 bit（ARGB1555）**，**没有 8bit alpha 纹理**。要更细的 alpha 只能用 `global_alpha`（8bit，逐精灵常数）与 `sprite_alpha`（4bit）相乘得到 8bit 混合系数。
- 混合命令的像素锥多一级串联乘法器（`展开 → alpha·ga(8×8) → ÷255 → mux → fg·A(8×8) → +127 → >>8 → 量化`），**运行期由 `blend` 门控、综合器剪不掉**；这是下次 P&R 最需要看的一条路径。

**配对纪律（新 demo 最重要的一条软件约定）**：
- 属性是**一条 FIFO**，引擎只是"每条命令弹一个"，它**不知道你写了几个**。
- 一旦开始用属性，就必须**每条命令都写、且只写一个**；想要默认行为的那条命令也要写 `ATTR_DEFAULT`。
- 不用属性时**一条都不写**（逐位回到旧语义）。**混着写必然错位**：后写的属性会被前面那条没写属性的命令吃掉。
- 工程做法：把这件事收敛到**唯一一个 `blt_emit()`**，任何命令都只能从这里出去 ⇒ 结构上不可能错位。

## 5. 显示列表格式（S2 / DFU）

### 5.1 列表缓冲地址（示例，FinalDemo 实际使用）

| 项 | 地址 |
|---|---|
| 几何表 | `DDR_BASE + 0x00800000`（= 0x801000），11 条 × 16B |
| 列表 0 | `DDR_BASE + 0x00820000` + 0×0x00020000（0x821000） |
| 列表 1 | 同上 + 1×0x00020000（0xA21000） |
| 上限 | 每张表 ≤ **4095 条**（`DL_COUNT_MAX`） |
| 对齐 | 列表基址与几何表基址**必须 16B 对齐** |

### 5.2 描述符记录 = **16 字节 = 4 字 = 恰好 1 个 128bit AXI beat**（小端）

```
dw0  [15:0]  X      (int16, 像素，相对 DL_DST_BASE)
     [31:16] Y      (int16, 像素)
dw1  [15:0]  SPR_ID (几何表索引)
     [31:16] FLAGS
dw2  [15:0]  KEY    (RGB565；0xFFFF = 用几何表的 KEY_DEFAULT)
     [23:16] ALPHA  (8bit 逐精灵透明度；**仅 OP=ALPHA 有效**)
     [31:24] PRIO   (0~255，仅软件排序/调试；本版硬件不排序)
dw3  [15:0]  MASK_ID  (S3 的 16 位 4×4 块位图)
     [23:16] W_OVR    (0 = 用几何表宽；1~255 = 覆盖宽，像素)
     [31:24] H_OVR    (0 = 用几何表高)
```
保留位**必须写 0**（前向兼容：将来在这些位上长功能）。

**`dw1[31:16] FLAGS` 逐位**：

| 位 | 名 | 语义 / 实现状态 |
|---|---|---|
| `[1:0]` | `OP` | **00=COPY 01=FILL 10=ALPHA 11=KEY**，与 `w0[1:0]` 逐位一致，直接搬运 |
| 2 | `MIRROR_X` | 水平镜像 —— **未实现**，置位 ⇒ `DL_ERR.UNSUPPORTED(bit24)` |
| 3 | `MIRROR_Y` | 垂直镜像 —— **未实现**，同上 |
| 4 | `CLIP_EN` | 越屏自动裁剪成屏内矩形；0 且 `STRICT_BOUNDS=1` ⇒ `SPRITE_BOUNDS` |
| 5 | `SIZE_OVR` | 1 = 用 `dw3` 的 `W_OVR/H_OVR` 而非几何表尺寸。★ **FILL + SIZE_OVR 时完全不读几何表** |
| 6 | `SRC_OFF_EN` | **未实现**，置位 ⇒ `UNSUPPORTED` |
| 7 | `MASK_EN` | S3 掩码生效（只有 `OP=KEY && W≥4 && H≥4` 才真的生效；其它 op 显式忽略） |
| `[9:8]` | `MASK_MODE` | **只实现 `01`**（1 = 该块全透明⇒跳过）；00/10/11 ⇒ `UNSUPPORTED(bit24)` |
| 10 | `END_OF_LIST` | 本描述符是列表最后一条（与 `DL_COUNT` 取**较小者**生效） |
| 11 | `IRQ_AFTER` | 本条命令完成后置 `IRQ_STATUS[2]` |
| 12 | `CHAIN` | **未实现**，置位 ⇒ `UNSUPPORTED` |
| `[15:13]` | 保留 | 写 0 |

**FILL 语义**：`X/Y` + `OP=01` + `dw2[15:0]` 作为**填充色**（此时 KEY 字段复用为 COLOR）。
**COPY/ALPHA/KEY 的源**：`SRC = GEOM.ATLAS_BASE + (SY + r)·GEOM.ATLAS_STRIDE + SX·2`（`SX/SY` 会被 `CLIP_EN` 的裁剪偏移修正）。

### 5.3 精灵几何表（16B/条）

```
gw0  [31:0] ATLAS_BASE     源图集起始字节地址（建议 16B 对齐）
gw1  [15:0] ATLAS_STRIDE   源字节行距
     [31:16] KEY_DEFAULT   默认键色（RGB565）
gw2  [15:0] W             精灵宽（像素，1~255）
     [31:16] H             精灵高（像素，1~255）
gw3  [15:0] SX            图集内列偏移（像素）
     [31:16] SY            图集内行偏移（像素）
```
- 地址 = `DL_GEOM_BASE + SPR_ID*16`；合法上界由 `DL_GEOM_MAX` 判（`SPR_ID ≥ GEOM_MAX ⇒ GEOM_INDEX`）。
- **16 条直接映射 cache**（索引 `spr_id[3:0]`、标签 `spr_id[15:4]`）⇒ **精灵种类 ≤16 且索引不撞**时命中率≈100%。要更多种类就得接受 miss（每次 miss 一笔 16B 读）。
- 为什么要单独一张表：同一精灵会被画很多次（子弹/敌机/战机一张图一帧几十次）；放进 16B 描述符会让描述符膨胀且每帧写带宽翻倍。

### 5.4 展开表：描述符 → 8 字命令（DFU 的纯组合映射）

| 命令字 | 来源 |
|---|---|
| `w0` | `{MASK[15:0], 13'd0, MASK_EN, OP[1:0]}` |
| `w1` | `OP==FILL ? 0 : (ATLAS_BASE + SY*ATLAS_STRIDE + SX*2)` |
| `w2` | `DL_DST_BASE + Y*DL_DST_STRIDE + X*2`（**带符号**加；越屏先由 `CLIP_EN` 裁剪再算） |
| `w3` | `ATLAS_STRIDE`（FILL 忽略） |
| `w4` | `DL_DST_STRIDE`（0x84） |
| `w5` | `{H, W}`（`SIZE_OVR` 时取 `dw3`，否则取几何表） |
| `w6` | `{24'd0, ALPHA}` |
| `w7` | `OP==FILL ? COLOR : (KEY==0xFFFF ? GEOM.KEY_DEFAULT : KEY)` |

展开后 `w2` 的非 16B 对齐、半词掩码等**全部仍由既有 `blt_addr_gen` + `pixel_path` 处理**——这正是"引擎零改动"的关键。

### 5.5 `DL_ERR`（0x60，R/W1C）错误码表

| 位 | 名 | 触发条件 |
|---|---|---|
| 0 | `DESC_RANGE` | 列表基址未 16B 对齐；`DL_COUNT>...` 之外的列表尾越出 32bit；描述符地址越界 |
| 1 | `GEOM_INDEX` | `SPR_ID ≥ DL_GEOM_MAX`（`GEOM_MAX=0` 且该命令需要几何表时也报） |
| 2 | `GEOM_RANGE` | 几何表地址越界 / 未 16B 对齐 / `GEOM_BASE + SPR_ID*16` 溢出 |
| 3 | `SPRITE_BOUNDS` | X/Y/W/H 越屏且 `CLIP_EN=0`（`STRICT_BOUNDS=1` 时） |
| 4 | `WATCHDOG` | 单条描述符超 `DL_TIMEOUT`（默认 4096 拍；固件提到 0xFFFF） |
| 5 | `AXI_RRESP` | R 通道 `rresp != OKAY` |
| 6 | `DESC_COUNT` | `DL_COUNT > 4095` |
| 7 | `ZERO_SIZE` | 裁剪后 W 或 H = 0 |
| `[23:16]` | `IDX` | 出错时的描述符序号 |
| `[24]` | `UNSUPPORTED` | `MIRROR_X/Y`、`SRC_OFF_EN`、`CHAIN`、`MASK_MODE≠01` |
| `[31:25]` | 保留 | 0 |

**出错后行为**：`BUSY` 保持 1 直到引擎 `done_out`（已下发的写必须落盘），然后 `BUSY=0, ERR=1`；`CONSUMED` 停在出错前条数；恢复 = 写 `DL_ERR` W1C → 修列表 → `DL_CTRL.GO`（**不需要 SOFT_RST**，引擎状态没被污染）。
**`ABORT` 语义**：只停"取指 + 展开 + 未入队"的命令；已进 cmd_fifo 的**照跑完**。软件以 `ABORTED=1 && BUSY=0` 作为"真的停了"。

### 5.6 实现与设计规格的 5 处偏差（照规格写会踩坑）

1. **屏幕尺寸**不在 §4 的表里 → 新增 `0x88 DL_FB_WH`（规格 §8.1 要求 `SPRITE_BOUNDS` 检查需要它）。
2. **目标行距**：规格 §14.7 建议复用 `0x70` 高半字；实现改为**另开 `0x84 DL_DST_STRIDE`**（以 §4 表为准）。
3. **掩码不进 ATTR FIFO**：规格 §13 设想 S2 顺手做一个平行属性 FIFO；实际 S3 用 **`w0[31:2]` 的空位**（`w0[31:16]` 掩码 + `w0[2]` 使能），因为两个 FIFO 严格同步一旦错位就是静默错掩码。
4. **`DL_ERR[24] = UNSUPPORTED`**（规格只列了 bit0~7）。
5. **`DL_CFG` 复位值 0x0000_0483**（= PREFETCH_EN + GEOM_CACHE_EN + CHUNK=8 + FIFO_WM=4）。

### 5.7 顺序与完成判据（不变式）

1. **展开顺序 = 描述符顺序 = 入 FIFO 顺序 = 引擎执行顺序**（DFU 单条流水；预取与译码并行但只写 FIFO 不写内存）。
2. 逐命令完成判据 `ST_WDWAIT` 出口 = `wd_empty && !wd_busy && wr_commit_idle`；**同一时刻最多一笔写突发在飞**是结构保证。
3. 预取最多把 `cmd_fifo` 灌满（256 字 = 32 条），**不会更前**——唯一出口是 cmd_fifo。
4. `DL_STATUS.DONE` = "可以安全改写这张列表"的硬件判据（内含 `wr_commit_idle`）。

### 5.8 双缓冲/三缓冲协议（列表乒乓 + 显示翻转）

- 列表：`DL_BASE0/1` 乒乓 + `DL_CTRL.BUF_SEL` 选本帧用哪张。
- 显示缓冲：`FB_SEL 0x24`（请求）→ `FB_STAT 0x28`（帧边界生效）；**三缓冲 0/1/2 与列表的 2 张互相独立**（列表="命令从哪来"，缓冲="画到哪/显示哪"）。
- 改写一张列表的软件流程：
  ```
  等 IRQ_STATUS.FRAME（0x10 bit1，场边界）  ← 把改写时机锁到场边界（最低要求可省，但会掉帧）
   && STATUS.BUSY==0（0x04 bit0）
   && DL_STATUS.DONE==1（且 BUF_SEL 指的是"上一帧那张"）
  ⇒ 改"上一帧用完的那张列表"；改完写 BUF_SEL=另一张，再写 DL_BASE*/COUNT/GO
  ```
- 推荐时序（帧 n）：取 `L[n%2]` → 写 `BUF_SEL/COUNT/DL_DST_BASE=B_n/GO`；画的同时改写 `L[(n+1)%2]`；`DONE` 后请求 `FB_SEL=B_n`；等 `FRAME` 确认翻转生效。
- 三缓冲的意义：渲染缓冲 B_n / 显示缓冲 B_{n−1} / 即将被覆盖的 B_{n−2} 三者互不重合。

### 5.9 `DL_TIMEOUT`

- `0x78[15:0]`，**core 拍**，复位 4096（≈41µs@100MHz），0 = 关闭。
- 计数从 `F_HEAD` 取到描述符起，8 个字写完停；超时 ⇒ `WATCHDOG` + `DL_FAULT_ADDR`。
- 为什么需要：AXI 从机不回 R、或 cmd_fifo 长时间满，DFU 会永远停在那里（软件看到"BUSY 永不落"）——看门狗把它变成一次可诊断的 ERR。
- **它不会打断已进 FIFO 的命令**；引擎侧卡死由 `STATUS.BUSY` + 软件超时处理。
- **板级现实**：ALPHA/KEY 场景里 desc 读会被引擎长突发饿过 65535 拍，所以看门狗会真的触发 ⇒ 固件策略是**最多重试 1 次，1s 窗口内第二次事件直接停用列表路径**。

### 5.10 ⚠ 显示列表路径**没有属性槽位**

16B 描述符 4 个字全部占满，**DL 路径不经过 `0x8C ATTR_PORT`**（属性只从 0x8C 来，DFU 不产生属性字）。
⇒ **要"每精灵不同 alpha / 不同混合模式"，只能用逐条下发路径**（CPU 每精灵写 1 个属性字 + 8 个命令字）。AdDemo 就是这么做的（文件头 (g) 明确写着这一点）。
⇒ 反过来，DL 路径的每精灵 alpha 只能靠 `dw2[23:16]`（8bit，只有 `OP=ALPHA` 用），混合模式只能是算子默认。

## 6. Alpha 混合与色彩键控的硬件实现与限制

### 6.1 混合公式与定点（金标准，逐位冻结）

```
out_ch = (fg_ch × A + bg_ch × (255 − A) + 127) >> 8        A ∈ [0,255]，255 = 不透明
```
- 三通道（RGB565）并行各算一遍；**先把通道展开到 8bit 再算**（提高精度、三通道对称）。
- 位复制展开（★ 抽头错一个就会整片偏色，`tb_alpha` 是守门人）：
  - `R8 = {fg[15:11], fg[13:11]}`（5→8）
  - `G8 = {fg[10:5],  fg[8:5]}`（6→8）
  - `B8 = {fg[4:0],   fg[2:0]}`（5→8）
- 位宽：`fg×A` 16bit（≤65025）；**两积之和必须 18bit**（≤130050 > 65535）；`+127` 后 `>>8`，取 `sum[15:8]`。
- 硬件：每 lane 每通道 2 个 8×8 乘法器（混合模式共 6 个；双 lane = 12 个），可推断 `EFX_DSP48`（Dual 模式一块做两个乘法）。全片实测 **21 DSP**（`u_blt` 16 个）。
- **已知 ±1 LSB**：因为分母是 255 不是 256，`A=255` 时结果可能比 fg 小 1 LSB（fg=200 → 199）。8bit 域误差 ~0.4%，进 5bit 通道后不可见。**不要"优化"成 256−α**（会和金标准/CPU 参考实现对不上）。
- 非 ALPHA 命令**旁路**乘法器（不吃 DSP 功耗/时序）。

### 6.2 alpha 的粒度与来源层级（限制清单的关键）

| 来源 | 位宽 | 生效范围 | 备注 |
|---|---|---|---|
| 命令字 `w6[7:0]` | **8 bit** | 逐命令常数（旧路径唯一来源） | `OP=ALPHA` 用 |
| 描述符 `dw2[23:16]` | **8 bit** | 逐精灵常数（DL 路径） | 展开进 `w6` |
| 属性 `global_alpha [13:6]` | **8 bit** | 逐命令（= 逐精灵，因为每精灵一条命令） | 255 = 不淡；**与常数 alpha 不同时给** |
| 属性 `src_format=2` ⇒ ARGB4444 | **4 bit/像素** | **逐像素** | 位复制成 8bit |
| 属性 `src_format=1` ⇒ ARGB1555 | **1 bit/像素** | 逐像素（二值） | 字段位置同 RGB565，bit15 = A |

- 有效系数 `A = floor(sprite_alpha · global_alpha / 255)`；`flags.bit1`（force-opaque）⇒ `A = 255`。
- **限制**：
  1. **没有 8bit 逐像素 alpha 纹理**。最细是 ARGB4444 的 4bit（16 级）；要更平滑只能靠 `global_alpha` 整体淡。
  2. **逐像素 alpha 与色彩键控不能在同一条命令里组合**（一个是 `OP=ALPHA` 的混合通路，一个是 `OP=KEY` 的比较器旁路）。要"先抠图再混合"目前做不到一条命令；替代方案：把透明区域写成 alpha=0 的 ARGB4444，用 `flags.bit0`（alpha 测试）产生硬边抠图效果（**注意 AdDemo 注释里 bit0 的语义写作"跳过 alpha 测试"，而 RTL 是"置位时做 alpha 测试 ⇒ 有效 alpha=0 不写"；以 RTL/`tb_attr_blend` 为准，上板先用单个精灵标定**）。
  3. **alpha 测试只在属性路径**（`OP` 为任意值都生效，`blend_mode=0` 时也生效）——DL 路径无法使用。
  4. `blend_mode` 与 `src_format` 都是**逐命令**的，不是逐像素的；一条命令内不能混。
  5. 属性字**只写、读不回**：无法探测硬件是否支持（AdDemo 用 CLIP/LUT 读回做间接探测 `feat_probe`）。

### 6.3 色彩键控（COLOR_KEY）

- 硬件 = 一个 **16bit 相等比较器** + 条件写：`OP=3` ⇒ `keep = (fg_px != key)`，`key = w7[15:0]`。
- **key 是可编程的**（每条命令一个 16bit RGB565 值）；`0xF81F` 只是软件/图集约定的"洋红"（`KEY_COLOR`）。**不是硬编码**。
- 留孔实现：像素不写 ⇒ 该 lane 的 2bit 字节掩码不置位；**整词全键色 ⇒ 只进位 jw、不提交**（省一笔写突发）。
- 与 α 的关系：抠图是"要么全写、要么不写"（硬边）；α 是"写一半"（软边/半透明）。
- **S3 透明块掩码**（4×4 块，16bit）：
  - 生效条件 `msk_on = MASK_EN && OP==KEY && W≥4 && H≥4`；**COPY/FILL/ALPHA 显式忽略掩码**（喂 0xFFFF 全透明掩码读数逐位不变，TB 里是反证用例）。
  - 粒度：列块边界 `floor(W·ct/4)`、行带边界 `floor(H·rt/4)`（`ct/rt = 0..3`）。
  - 落地 = **行窗口**：每行只取/只画 `[第一个非透明列块起点, 最后一个非透明列块终点]`；4 个列块全透明 ⇒ 该行 **0 取数、0 像素、0 写**。
  - **只收缩行的两端**；中间的透明块**不会跳**（仍走一遍，KEY 自然留孔、不写）——要跳中间的块必须把一行取数拆多笔突发（未实现）。
  - 收益**完全取决于美术**：圆盘内切包围盒的精灵（demo 球）**0%**；覆盖率 35~50% 的弹幕弹 −4.5%（16×16）/−21.4%（32×32）；上下整带透明的 32×32 小弹 **−68.1%**（1419 → 452 拍）。
  - **掩码写错没有任何错误位可诊断**（只会少画）⇒ 只在"图集是常量、掩码随图集预算"的场合用。

### 6.4 源像素格式（`src_format`）

|---|---|---|---|
| 0 | RGB565 | R[15:11] G[10:5] B[4:0] | 默认；帧缓冲/图集标准 |

### 7.3 带宽（不是瓶颈，但要知道量级）

- DDR3 峰值 **1.6 GB/s**（16bit × 800Mbps）；实测可用 ~1.0~1.2 GB/s。
- 扫描输出 960×540×2B×60 = **62.2 MB/s**；每趟整片重铺 960×260×2B ≈ 30 MB/s。
- 每像素访存：FILL 写 2 B；COPY/KEY 读 2 B + 写 2 B；**ALPHA 读 fg + 读 bg + 写 = 6 B**。
- 按瞬时吞吐算的 DDR 占用：**9% ~ 28.5%**（最高 = 64×64 ALPHA 457 MB/s）；"每像素 3 次访存 × 100 Mpx/s 线速"的外推是 600 MB/s = 37.5%。
- 结论：**带宽不是墙，墙是像素通路本身**（双 lane 之前 1 px/拍）。ALPHA 的 DDR 流量是双 lane 之后最先会变成约束的东西（外推 ~960 MB/s ≈ 60% 峰值）。

### 8.2 新 demo 的最小骨架（照 `blt_emit()` 抄）

```c
/* 唯一的命令出口：属性字与命令 8 字在这里成对出现 ⇒ 结构上不可能错位 */
static void blt_emit(uint32_t attr, uint32_t op, uint32_t src, uint32_t dst,
                     uint32_t ss, uint32_t ds, uint32_t w, uint32_t h,
                     uint32_t alpha, uint32_t color)
{
    if (g_attr_on) W(BLT_ATTR_PORT, attr);      /* ★ 必须在 8 个字之前 */
    W(BLT_CMD_FIFO_DATA, op);
    W(BLT_CMD_FIFO_DATA, src);
    W(BLT_CMD_FIFO_DATA, dst);
    W(BLT_CMD_FIFO_DATA, ss);
    W(BLT_CMD_FIFO_DATA, ds);
    W(BLT_CMD_FIFO_DATA, (h << 16) | (w & 0xFFFF));
    W(BLT_CMD_FIFO_DATA, alpha);
    W(BLT_CMD_FIFO_DATA, color);
}
/* 抠图精灵（RGB565 + 洋红键色）—— 属性打开时也要写 ATTR_DEFAULT */
e_key(now_attr, src, dst, SPR_STRIDE, FB_STRIDE, SPR_W, SPR_H, 0xF81F);
/* 半透明精灵：alpha 放 w6，属性写默认字（两者不同时给） */
e_alpha(now_attr, src, dst, SPR_STRIDE, FB_STRIDE, SPR_W, SPR_H, 128);
/* 加算辉光：ARGB4444 + 每精灵 global_alpha（属性侧口） */
e_alpha(attr_word(2/*ADD*/, 2/*4444*/, ga, 0), src, dst,
        SPR_STRIDE, FB_STRIDE, SPR_W, SPR_H, 0xFF);   /* w6=0xFF = 无 */
```

### 8.3 下发节奏与 FIFO 余量

- `CMD_FIFO_COUNT` 单位是**命令条数**（深度 256）。**属性字进另一条 FIFO，不占命令条数**（余量记账与只写命令时一致）。
- 实用阈值：`BLT_PUSH_LIMIT = 256 − 56 = 200` 条（留 56 条余量）；写满会被硬件反压（`awready` 拉低），但**软件自旋更慢**，所以先在软件侧限流。
- 期望 1 Hz 成本行（AdDemo/FinalDemo 都有）：
  `EV cmd path done: n=<精灵数> cycles=<秒表> cyc/sprite=<cycles/n>`
  `EV dl  list done: n=<精灵数> cycles=<DL_PERF> cyc/sprite=<cycles/n>`
- 等空闲：`(STATUS & DONE) && (STATUS & FIFO_EMPTY) && !(STATUS & ERR)`；**所有等待必须有界**（AdDemo 用 200ms 上界 + 打印诊断 + 软复位恢复；引擎 `STATUS.ERR` 是电平锁存，只有 SOFT_RST 能清）。

### 8.4 帧节奏与呈现

1. `IRQ_EN[1] = 1`（FRAME）或直接轮询 `0x10 bit1`；`0x28[31:16]` 场计数可直接当帧号。
2. 三缓冲轮转：`DRAW_SEL = 本趟目标` → 画 → `FB_SEL = 本趟目标` → 有界等 `FB_STAT[1:0] == 目标`。
3. 清屏交给 `clr_engine`（后台清**第三块**，`CLR_STAT[5:2]` 的 clean 位图作判据；**写 `DRAW_SEL` 会清 clean 位，顺序必须是"先读 clean、再写 DRAW_SEL"**）。
4. **缓存一致性**：CPU 直写 DDR（烘焙图集/背景）后，引擎/扫描输出直读 DDR 会看到旧数据。D$ 是写穿策略，屏障做法 = 往一块 8KB scratch 写一遍（`cache_evict()`）。AdDemo 的渲染路径 CPU 一个像素都不写 ⇒ 只在开机烘焙后冲一次。

### 8.5 ★ 五个已经踩过的坑（照抄结论，别重踩）

1. **属性配对**：用属性就"每条命令恰好 1 个"，包括要默认行为的那条；关掉属性就一条都不写。收敛到唯一的 `blt_emit()`。
2. **scissor 坐标是"本条命令目的矩形的局部坐标"**，不是屏幕坐标。信息条/HUD/边框/底图这类"屏幕骨架"命令的 dst 在 (8,4) 这种位置，平移后窗口与矩形无交集 ⇒ **整条消失**（上板症状：场景 3 信息条与 HUD 不见了）。AdDemo 用 `CLIP_GUARD`（下发出口唯一守卫）+ `clip_off_verified()`（回读确认）两道保证"骨架只在 scissor 关着时下发"。另：**引擎在命令起始锁存 scissor ⇒ 每条命令要不同窗口就必须在引擎空闲时改寄存器**（AdDemo 把"窗口变化的等待"做成有界步骤）。
3. **LUT bank 极性**：发布值 = **写 bank 的反相 = 写表之前读到的那个显示 bank**（见 §2.6 四步序列）。照早期规格写会导致"表写进去一辈子不上屏"。
4. **`0x4C~0x88` 在 `DL_STATUS.BUSY=1` 期间写入被静默忽略**，读回旧值；要改必须先 ABORT 或等 DONE。
5. **BSP printf 是 mini 版，只认 `%c %s %d %X %x`**：出现 `%u`、宽度数字、`%%` 会错位消耗 `va_arg`，后面的 `%s` 拿整数当指针**直接挂死**。无符号量先强转成 `(int)` 再用 `%d/%x`。

### 8.6 用 DL 还是用逐条？—— 对新 demo 的明确建议

| 需求 | 建议路径 | 理由 |
|---|---|---|
| **每精灵不同 alpha / 不同混合模式（加算、乘法、ARGB4444）** | **逐条下发（CPU 写属性 + 8 字）** | ★ DL 描述符**没有属性槽位**，属性只从 `0x8C` 来 |
| 每精灵 alpha（8bit 常数，仅 ALPHA op） | DL 可用（`dw2[23:16]`） | 但读密集场景 desc 取指会被饿过看门狗 |
| 极高精灵数、参数同构、几何固定（弹幕批量） | DL 值得试（+4.3% 同口径） | 收益有限（实测只有 ~55 拍/精灵没能重叠），且 ALPHA/KEY 场景板级会被看门狗打断 |
| 高精灵数 + 每精灵属性 | **逐条 + 属性**（AdDemo 路线） | CPU 侧每精灵 9~10 次 MMIO（约 15~25 拍/属性写），5,300 精灵 ≈ 0.1M 拍 ≈ 帧预算的 7% |

### 8.7 容量预算（新 demo 开画前先算）

- 图集区：`DDR_BASE+0x00100000` 起；AdDemo 用 0x201000（RGB565 圆盘）/0x210000（ARGB4444 辉光）/0x220000（8×8 字形）。
- 帧缓冲：0x301000 / 0x501000 / 0x701000（各 0xFD200 B < 1MB）。
- 背景大图：AdDemo 用 0x604000（960×524×2 = 0xF5A00 ⇒ 0x604000+0xF5A00 = 0x6F9A00 < 0x700000 ✓）。
- **几何表条目 ≤ 需要 cache 的精灵种类**（16 条直接映射）；超过会 miss（每 miss 一笔 16B 读，可接受但会影响取指公平性）。
- 4×4 掩码收益的几何阈值：`R/W ≥ 0.442`（16×16）/ `≥ 0.398`（32×32）⇒ **一块都标不上**；`R/W ≈ 0.219` ⇒ 跳过 12/16 块（75% 像素）；子弹类覆盖率 35~50% ⇒ 跳过 3~4 块。

### 8.8 新 demo 的 bring-up 顺序（照 §9.4 的冒烟序列）

1. 读 `0x80 DL_VERSION`、`0x0C CMD_FIFO_COUNT`、`0x04 STATUS` 确认 APB 窗口接通（读数全 F / 全 0 ⇒ 位流没加载或基址不对）。
2. `CTRL.SOFT_RST=1 → 0`；清 `0x10`；`IRQ_EN` 按需；`CTRL.GO=1`。
3. `blt_fill` 整屏一色 → 屏幕上应该有整片颜色（验证扫描输出 + 写通道）。
4. `blt_copy` 搬一块 → 验证读通道 + 非对齐。
5. `blt_key`（0xF81F）画一个不规则精灵 → 验证抠图（留孔）。
6. `blt_alpha` 画半透明叠加 → 验证混合公式（金标准：α=128 时 0x7BEF 系列值；AdDemo 自检有 L1~L6 手算表）。
7. `feat_probe`：写/读 `0x90~0xA0`、`0xA4~0xB0`；都通 ⇒ 认为属性侧口也在（0x8C 不可读回，只能间接判）。
8. 打开属性：`ATTR_DEFAULT` + 加算辉光（ARGB4444）→ 看观感。
9. `scissor`：先在**全屏目的矩形**的命令上试（局部坐标 == 屏幕坐标），再引入"骨架/内容分类"。
10. `LUT`：先灌恒等表验证无损，再灌 fade/flash；bank 极性按 §2.6 四步。
11. 压测：`N` 从 16 逐步加到帧预算边缘，读 1 Hz 成本行的 `cyc/sprite` 与 `MPX`。

## 10. 不确定项 / 需要在板上标定的地方（诚实清单）

1. **0x8C ATTR_PORT 不可读回** ⇒ 只能靠 `0x90~/0xA4~` 的读写校验间接推断存在性；属性字本身的落地要靠观感与 `PERF` 不变（±1%）来判。
2. **`flags.bit0` 的语义在文档与代码间有措辞冲突**：AdDemo 注释写"跳过 alpha 测试"，RTL/`tb_attr_blend` 是"置位时做 alpha 测试 ⇒ 有效 alpha=0 不写"。上板先用单精灵标定。
3. **属性 `global_alpha` 与命令字 `w6` 的 alpha 谁优先没有规定** ⇒ 采纳 AdDemo 的做法：**从不同时依赖两者**（用属性时 `w6=0xFF`；用 `w6` 时一条属性都不写）。
4. **v3.2 双 lane 的板级吞吐数字尚未归档**（§7.2 全是仿真；§7.1 全是 v2.16 单 lane 板测）。板上判据：整屏 FILL `PERF 0x1C` 从 ~586k 降到 ~295k 量级。
5. **读路径公平性是现在就妨碍演示的缺陷**（desc 取指会被饿过看门狗）⇒ 新 demo 的高精灵数路线优先"逐条 + 属性"。
6. **DL 路径没有属性槽位**：若要让 DL 也支持逐精灵属性，需要先定义"属性从哪来"（RTL/接口改动）。
7. `MIRROR_X/Y`、`SRC_OFF_EN`、`CHAIN`、`MASK_MODE≠01`、逐像素掩码（8bit alpha 阈值）**都未实现**，置位即 `DL_ERR.UNSUPPORTED(bit24)`。
8. **重叠拷贝（src/dst 矩形相交）不支持**：驱动约定不产生重叠指令。
9. 仓库**不是 git 仓库**（无 `.git`），版本线索只能靠文档里的提交号与 `firmware/` 留档。
