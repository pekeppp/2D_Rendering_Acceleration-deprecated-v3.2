## 2. 测量工具链（[成果] §2 自称"本批最值钱的部分"）

### 2.1 1 Hz 成本行（唯一的板级仪表）

固件在两条路径上各打一行**同口径**成本（`FinalDemo.c` 的 `dl_cost_report()` / `cmd_cost_report()`，提交 `725134c`）：

```
EV cmd path done: n=<精灵数> cycles=<软件秒表> cyc/sprite=<cycles/n>
EV dl  list done: n=<精灵数> cycles=<DL_PERF>  cyc/sprite=<cycles/n>
```

| 要点 | 内容 |
| --- | --- |
| 门控 | **1 Hz**（`DL_COST_TICKS = BSP_CLINT_HZ`）——不是每帧、更不是每条，串口不会被刷屏 |
| 单位 | 都是 **core 拍**。列表那行用 `DL_PERF(0x7C)`（取指器在 core 域计数）；逐条那行是 CLINT `mtime` 秒表 |
| 口径差（**必须知道**） | 列表行 = **纯硬件**（GO→DONE）；逐条行 = **墙钟**（含每块 8 次 MMIO 的 CPU 下发）——后者正是按 `l` 想省掉的东西 |
| 已知污染 | 列表行的 `n` 只数精灵，`cycles` 里却含同一张表里那条**整片重铺**描述符（W=960 的 FILL）⇒ 小 N 时 `cyc/sprite` 明显偏高；比大小要把 N 加大（N=976 时重铺只占 3%） |
| 价值 | 本批**每一个**性能数字都出自这一行；它推翻了 4 条旧结论（§9.1） |

### 2.2 两点 / 三点拟合：`A + B × px` 模型

| 步骤 | 做法 |
| --- | --- |
| 采样 | 三尺寸各测一趟：16×16（256 px）/ 32×32（1 024 px）/ 64×64（4 096 px） |
| 两点定参 | 用**两端点**（16×16 与 64×64）解 `A`（每精灵固定开销）与 `B`（每像素成本） |
| 三点验残差 | 中间点（32×32）不参与拟合，专门验模型 |
| 外推 | 渐近线吞吐 = `1/B` px/拍；兑现率 = 实测吞吐 ÷ 渐近线 |
| 粒度 | N 由串口/网页按 **步进 25** 调（范围 **25–6000**）⇒ 相对不确定度 = 25/n |

| 纪律 | 落地 |

### 2.4 口径陷阱清单（[成果] §2.5，"本批踩过的"）

| 陷阱 | 后果 |
| --- | --- |
| 拿"纯硬件列表"与"含 CPU 的逐条墙钟"直接比大小 | 得到"列表净亏 43%"的错误结论；实测 CPU 下发**大部分与引擎重叠**，真正省下的只有 ~55 拍/精灵 |
| 用不同 N 的两行相减 | 每精灵固定开销 / 整片重铺摊薄比例不同，差值里混着 N 的差 |
| 在模式切换与回退重绘期间采样 | 那一趟里既有列表路径又有逐条补画，`cycles` 不是任何一种路径的成本 |
| 把"板 − 仿真"整段当本地归给某个模块 | 那条差里同时含 DDR 竞争、B 往返、CPU 重叠程度 |
| 忘记测量粒度 | 64×64 只跑 350 个精灵、步进 25 ⇒ **±7%**；这一档任何 3~4% 的差异都落在一格之内 |
| **双 lane 下按拍统计的探针量** | `px_cons/px_skipped/max_px_run` 在 v3.1 后 1 拍 = 2 像素 ⇒ `px_cons` 518,400→259,200、`max_px_run` 960→480；**像素数一律看 `px_written`**（[探针] §9、功能清单 §27.5） |

### 5.3 v3.2 (S5) 新增寄存器 0x8C~0xB0

| 偏移 | 名称 | R/W | 位定义 / 协议 |
| --- | --- | --- | --- |
| **0x8C** | `ATTR_PORT` | W | 每写 1 次 = 往**属性 FIFO（深 16、FWFT）**压 1 个 32bit 属性字；引擎在**每条命令起始（ST_DEC）按序弹 1 个** ⇒ 严格"先写属性、再写命令"。FIFO 空 ⇒ 默认字（blend 0 / RGB565 / ga 255 / flags 0 = `0x0000_3FC0`）。位域：**[3:0] blend_mode**（0=按算子默认 1=alpha 混合 2=加算饱和 3=乘法，4~15 保留→按 0）**[5:4] src_format**（0=RGB565 1=ARGB1555 2=ARGB4444，3 保留→按 0）**[13:6] global_alpha**（255=不淡）[15:14]/[23:16] 保留 **[31:24] flags**（bit0=alpha 测试：alpha=0 不写；bit1=强制不透明按 255 算）。**不看 WSTRB**，整字入队 |
| **0x90 / 0x94 / 0x98 / 0x9C** | `CLIP_X0 / X1 / Y0 / Y1` | RW | scissor 边界，**半开区间** `X0 ≤ x < X1`、`Y0 ≤ y < Y1`。坐标是**本条命令目的矩形的局部坐标**（原点 = 该行 `dst_base` 第一个像素） |
| **0xA0** | `CLIP_CTRL` | RW | bit0=ENABLE（**复位 0**）。引擎在**命令起始锁存** ⇒ 命令中途改不会撕裂本命令。启用后：矩形外像素不写；**整行在矩形外的行不取数、不算**（走 S3 的"空窗口跳过"分支） |
| **0xA4** | `LUT_ADDR` | RW | [9:8]=通道（0=R 1=G 2=B，3 保留→该次写忽略）[7:0]=表内下标 |
| **0xA8** | `LUT_DATA` | W | [7:0] 写入当前下标/bank 的输出值（**写它就产生 1 拍写脉冲**） |
| **0xAC** | `LUT_CTRL` | RW | bit0=ENABLE（请求，**立即**生效）bit1=**`LUT_DATA` 写进哪个 bank**。bit0/bit1 只在**帧边界**被锁存成"显示用的值"；**显示读的是锁存 bit1 的反相** ⇒ 写口与显示口永远指向不同 bank |
| **0xB0** | `LUT_STAT` | R | bit0 = **正在显示**的 bank |

> ★ **LUT 发布序列（AdDemo 头注释把它列为"实测标定"的坑）**：① 读 `0xB0` 得 D；② `0xAC bit1 = ~D`
> （新表整张写进非显示 bank）；③ 写 3×256 项；④ `0xAC bit1 = D` ⇒ 帧边界锁存后显示 = ~D = 刚写的表。
> 早期规格写的"bit1 = 刚写的 bank"**差一个反相**，照它做显示 bank 永远不动（表写进去却一辈子不上屏）。
> 另：开 LUT 前必须把整张表写完（RAM 上电为 0 ⇒ 未写的表 = 全黑）；写表期间**不要翻 `0xAC bit1`**。

### 5.4 8 字命令格式（`CMD_FIFO_DATA` 连写 8 字；`blt_cmd_t` 布局）

| 字 | 字段 | 说明 |
| --- | --- | --- |
| **w0** | `op[1:0]` + 掩码空位 | `0=COPY 1=FILL 2=ALPHA 3=KEY`（其它值 → ERR，跳过本条）。**S3 之后**：`w0 = {MASK[15:0], 13'd0, MASK_EN, OP[1:0]}` ⇒ `w0[31:16]` = 4×4 透明块位图、`w0[2]` = 掩码有效位。CPU 侧写 0 ⇒ 行为与之前逐位相同 |
| **w1** | `src_addr[31:0]` | 字节地址（FILL 忽略） |
| **w2** | `dst_addr[31:0]` | 字节地址 |
| **w3** | `src_stride[31:0]` | 源行距字节（FILL 忽略） |
| **w4** | `dst_stride[31:0]` | 目的行距字节 |
| **w5** | `width[15:0]` / `height[31:16]` | 像素宽 / 行高 |
| **w6** | `alpha[15:0]` | 0~255（仅 ALPHA） |
| **w7** | `color[31:0]` | FILL 填充色 / KEY 键色 |

**状态语义（不可改）**：`run_en(GO)=1` 时引擎 FIFO 非空即 POP 执行，执行完再查 FIFO；`FIFO 空 && 引擎 IDLE` → `DONE=1`（电平）。
CPU 批量下发可超 FIFO 深度而不死锁的前提正是这个语义。

**S3 掩码安全规则**：`msk_on = MASK_EN && OP==KEY && W≥4 && H≥4`；**FILL / ALPHA / COPY 显式忽略掩码**
（用 `0xFFFF` 全透明掩码反证：读数逐位不变）。掩码由软件算（固件 `build_atlas()` 里的 `spr_mask_of()`），
**写错没有任何错误位可诊断，只会少画**。

```
       [10]END_OF_LIST [11]IRQ_AFTER [12]CHAIN [15:13]保留
```

展开（`dl_fetch.v` 纯组合）：`w0={30'd0,OP}`（**注意：S3 掩码经 `x_w0 = {MASK_ID,13'd0,MASK_EN,OP}`**）、
`w1 = FILL?0 : ATLAS_BASE + SY*STRIDE + SX*2`、`w2 = DL_DST_BASE + Y*DST_STRIDE + X*2`（带符号）、
`w3=ATLAS_STRIDE`、`w4=DST_STRIDE`、`w5={H,W}`、`w6={24'd0,ALPHA}`、`w7 = FILL?COLOR:(KEY==0xFFFF?KEY_DEFAULT:KEY)`。
DFU 从 DDR 读 16 B/条 → 查几何表 → 展开成**现有 8 字命令** → 推进**现有 cmd_fifo**；**引擎 FSM / 像素通路 / 地址生成一行未改**。
desc 读复用 `axi_rd_master` 的第三个 tag（`rd_sel=10`，优先级 fg > bg > desc + `AGE_MAX=64`）。

### 6.3 AdDemo：场景 / 命令集（v3.2 现状，做新 demo 的最佳模板）

| `k` | 精灵尺寸循环 |

| `a`/`A` | master alpha 减/加 |
| `f` / `b` | LUT fade/flash 总开关 / 立刻白闪一次 |
| `x` | **scissor 开关（A/B，场景 3）** |

信息条字段：`FPS=nn N=nnnn SZ=nn MPX=nnnn SCd:NAME A=nnn B=nnn [FR][F][X][Y][Q]` + 右侧 `HW ONLY`。
- **FPS = 真正上屏的帧率** = 翻转被扫描输出**确认生效**的次数/秒（FLIP 口径）；
- **MPX = N × SZ × SZ × FPS / 1e6**（由精灵数与尺寸算出的等效像素吞吐，Mpx/s）；
- **B = 引擎 busy 百分比（采样）**；`FR F X Y Q` = 模式标志位。
- 信息条最坏宽度已被主机自检约束：`"FPS=99 N=6000 SZ=64 MPX=9999 SC4:LAYER A=255 B=100 FR F X Y Q"` = 61 字符 = 488 px（文本 x=[8,496)，标签 x=[896,960)）。

**AdDemo 的"配对纪律"（新 demo 必须照抄的一条）**：ATTR 是**一条 FIFO**，引擎只是"每条命令弹一个"，它**不知道你写了几个**。
⇒ 一旦开始用属性，就必须**每条命令都写且只写一个**（想要默认行为的那条也要写 `ATTR_DEFAULT=0x00003FC0`）；
不用属性时**一条都不写**（按 `y` 关掉侧口）。混合"写了/没写"必然错位（后写的属性被前面那条没写属性的命令吃掉）。
AdDemo 把这件事收敛到**唯一一个函数 `blt_emit()`**，没有命令绕过它 ⇒ 结构上不可能错位。

**AdDemo 的两处上板 bug（对写新固件是直接教训）**：
1. 字形图集的"源行跨度（16 B）"与"字形间距（128 B）"被当成同一个数 ⇒ 信息条糊；
2. `FADE_PERIOD_MS`/`FLASH_MS` 是**毫秒**却被当 CLINT **拍数**用（100 MHz ⇒ 1 ms = 100,000 拍）⇒ "场景 2 不淡、场景 4 惨白"。
3. 另修：所有"等引擎"的等待改为**有界**（`ST_WAIT_TICKS=200 ms`，超时打印诊断 + 软复位引擎 + 重开本趟）——
   引擎一旦进去 `STATUS.ERR`（电平锁存，只有软复位能清），原来的无限空转会让屏幕冻死、切场景也切不回去。

## 8. 软件 vs 硬件渲染对比是怎么做的

| 手段 | 说明 | 来源 |
| --- | --- | --- |
| **SPLIT 同屏对比** | `s` 键进入 `PATH_SPLIT`：**左半屏硬件画、右半屏 CPU 逐像素直写**，同一屏、同一帧、同一场景数据 ⇒ 肉眼与计数都能直接比 | tools/README.md §3.1、FinalDemo.c |
| **三计数器共享窗口** | 屏幕信息条 `HW=` / `CPU=` / `SCR=`（published frames/s），1 Hz 一起清零 ⇒ 横向可比 | FinalDemo.c:2188-2196 |
| **同口径成本行** | 两条路径各打 `cycles` + `cyc/sprite`（1 Hz，串口） | [成果] §2.1 |
| **单变量 A/B 纪律** | 同场景、同 N、同尺寸，只翻一个开关（`l`/`k`/掩码/`e`/`x`/`y`）读前后两行 | [成果] §2.4 |
| **作废的错误做法** | ① 拿"纯硬件列表"比"含 CPU 的逐条墙钟"；② 用不同 N 的两行相减；③ 在模式切换/回退重绘窗口采样；④ 把"板−仿真"整段归给某模块 | [成果] §2.5、§5 |
| **软硬件位精确对照** | `tb_dl_demo` 把固件真实描述符字节喂进真实 RTL 比命令字 + 比像素；主机自检在 PC 上跑固件被标记的源码段 | [成果] §2.3 |

> **`软/硬件` 对比的三个数字口径要分清**：
> (1) 列表行 = **纯硬件** GO→DONE（`DL_PERF`）；(2) 逐条行 = **墙钟**（含 CPU 下发）；
> (3) 屏幕 `FPS` = **真正上屏（FLIP 确认）** 的帧率；`MPX` 是由 N/SZ/FPS **算出来**的等效吞吐，不是实测带宽。

### 9.2 瓶颈的根本判断（[成果] §6）

1. **吞吐的墙 = 像素通路**（v2.16 时是单 lane 1 px/拍；v3.1 已加宽到 2 px/拍）。
   `B_FILL = 1.025` 拍/px（= 0.976 px/拍 = 97.6 Mpx/s 渐近线）；整屏 FILL 实测 0.9958 px/拍；
   `A_FILL = 252` 拍只占 64×64 的 5.7%、占 16×16 的 49% ⇒ **尺寸档杠杆用尽**。
2. **DDR 带宽不是限制**：实测口径下占用 **9%~29%**（最高 64×64 ALPHA 28.5%），按线速外推也只有 37.5%；
   写侧独立证据：AW 合并后 1.13 拍/词 ⇒ 可持续 ~1.42 GB/s。
3. **DDR 延迟 / 公平性是真弱点**：描述符读最长等待 **64 拍 = `AGE_MAX`**（提权生效）；
   **非引擎读流（CPU）在引擎压满读口时等 39 998 拍**（窗口 40 000 拍）；板上描述符读被饿过 `DL_TIMEOUT`
   （看门狗在**随机序号**触发、`stall_seen=1` = 被饿住不是死了），**超时值已提到字段上界 65 535 拍仍会触发**。
   ⇒ 判断：**"带宽够、延迟/公平性不够"**；描述符取指只占 18.3% 授权份额，却会被引擎长突发排到 65 535 拍之外。
4. **读路径公平性是现在就妨碍演示的缺陷**（ALPHA/KEY 场景列表路径会被看门狗打断并停用 ⇒ 那些场景收益为 0）。

## 10. 面向"新高负载交互式游戏 Demo"的设计要点（把上面变成可执行约束）

### 10.1 容量预算（用 [成果] 的 `A + B×px` 模型，单位 = 精灵/帧 @60 fps）

按 **1 666 667 拍/帧**，且假设能用满**整帧**（现实中要留出扫描输出/清屏/OSD/翻转的余量）：

| 场景 | 每精灵拍数（板上 v2.16 口径） | 理论容量/帧 | 建议设计余量（≤70% 帧预算） |
| --- | --- | --- | --- |
| 16×16 FILL | 514.3 | ~3 240 | **≤2 270** |
| 16×16 KEY | 719.1 | ~2 318 | **≤1 620** |
| 16×16 ALPHA | 856.4 | ~1 946 | **≤1 360** |
| 32×32 FILL | 1 263.8 | ~1 319 | **≤920** |
| 32×32 KEY | 1 617.4 | ~1 030 | **≤720** |
| 32×32 ALPHA | 1 969.0 | ~846 | **≤590** |
| 64×64 FILL | 4 450.0 | ~375 | **≤260** |
| 64×64 ALPHA | 6 742.7 | ~247 | **≤170** |

- **v3.1 双 lane 之后的同口径数字尚未上板**：仿真上 32×32 FILL 1 199→687（1.75×）、16×16 FILL 366→239（1.53×）、
  KEY/COPY 类 1.67~2.48× ⇒ 上表可以按 **1.5~1.8×** 放宽估计（保守），但**必须自己上板复测**再定 KPI。
- 帧内**非本趟**开销实测 6.5%~15.9%（16×16 FILL 是离群点 15.9%）⇒ 不要把帧预算算满。
- **60 fps 之外的另一条口径**：屏幕 `FPS` 是"发布上屏"帧率；设计目标建议直接盯 `MPX = N·SZ²·FPS/1e6` 与 `B`（引擎 busy%）。

### 10.2 必须遵守的接口契约（新固件按这份清单写）

1. **命令 = 8 个 32bit 字连写 `0x08`**；`op = w0[1:0]`（0 COPY / 1 FILL / 2 ALPHA / 3 KEY）；非法 op ⇒ `STATUS.ERR` **电平锁存，只有软复位能清**。
2. **`CTRL.GO` 必须先写 1**（使能自动消费）；`STATUS.DONE = FIFO 空 && 引擎 IDLE`（**电平，不是脉冲**）；批量下发可超 FIFO 深度。
3. **上屏用 FLIP，不要每帧整屏 COPY**：写 `FB_SEL(0x24)` → 轮询 `FB_STAT(0x28)[1:0]`（**有界超时**）或按 `FB_IRQ_PACING` 用 `IRQ_STATUS[1]` 帧中断驱动；请求只在**帧边界**生效。
4. **清屏交给 `clr_engine`（0x2C~0x48），并遵守 `DRAW_SEL(0x44)` 互斥**：每趟开画前写 `DRAW_SEL` = 本趟目标；`CLR_STAT[6]` sticky ERR 要清；`CLR_WAIT_TICKS` 建议 10 ms（实测整片清 ≈ **2.1 ms**）。
5. **用 `ATTR_PORT(0x8C)` 就必须"每条命令恰好写一个属性字"**，收敛到唯一 emit 函数；不用就一条都不写。FIFO 深 16 ⇒ 最多领先 16 条。软复位清空属性 FIFO。
6. **scissor 坐标是本条命令目的矩形的局部坐标**（半开 `[x0,x1)×[y0,y1)`）；引擎在命令起始锁存 ⇒ 换窗口要在**引擎空闲**时写；屏幕骨架（HUD/信息条）只在 `CLIP_CTRL=0` 时下发。
7. **LUT 发布四步**（读 0xB0 → `0xAC bit1 = ~D` → 写 3×256 → `0xAC bit1 = D`）；开 LUT 前把表写完；写表期间不要翻 bank。
8. **掩码（S3）只能配 KEY，且 `W≥4 && H≥4`**；FILL/ALPHA/COPY 显式忽略；掩码错没有错误位。
9. **DL（显示列表）在当前板上不可靠**：ALPHA/KEY 场景描述符取指会被饿过 `DL_TIMEOUT`（65535 拍）⇒
   固件最多重试 1 次就停用。**新 demo 建议只用逐条下发路径**（也是 AdDemo 的选择），或只对"少读几何表/FILL 为主"的列表用 DL。
10. **1 Hz 成本行必须保留并归档**（`doc/logs/board_costline_*.txt`）：同口径、同 N、同场景比两行，这是唯一能证收益的仪表。
11. **`%d/%x/%s/%c` only** 的 printf 约束；所有"等引擎"的等待都要**有界 + 超时可恢复**（软复位 + 重开本趟）。
12. 高负载交互（按键/输入）的响应路径不要放在"等引擎"的循环里：AdDemo 的做法是"任何时刻都能切场景，串口命令循环绝不被阻塞"。
