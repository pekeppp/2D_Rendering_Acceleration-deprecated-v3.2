# DDR3 内存分配分析（Ti60F225，256MB）

> 依据：板卡官方 demo（08_ti60f225_soc_demo）生成的 `soc.h`、`freertos.ld`、
> `bootloaderConfig.h`；MT41J128M16（2Gb x16, 800MT/s）；本队方案（双帧缓冲 +
> 精灵图集 + BitBlt 引擎/扫描输出 AXI 访问）。

## 1. 先确认的硬事实（官方 demo 实测配置）

| 项 | 值 | 来源 |
| --- | --- | --- |
| **DDR 逻辑基址** | **0x0000_1000**（外部存储 BMB 窗口基址，可配） | 官方 soc.h: `SYSTEM_DDR_BMB 0x1000`，窗口 3.5GB |
| DDR 物理容量 | 256MB → 逻辑范围约 `0x1000 ~ 0x1000_1000` | 板卡 |
| 程序镜像加载目标 | `0x0000_1000`（bootloader 从 Flash 拷入后跳转） | bootloaderConfig.h: `USER_SOFTWARE_MEMORY 0x1000` |
| **单次拷贝上限（默认）** | **0x1F000 = 124KB** | bootloaderConfig.h: `USER_SOFTWARE_SIZE 0x1F000` |
| 程序镜像存放（Flash） | SPI Flash 偏移 `0x0038_0000`（8MB Flash，与 bitstream 分占） | bootloaderConfig.h: `USER_SOFTWARE_FLASH 0x380000` |
| I$/D$ 缓存行 | **64 字节**（4KB 各，1 路） | soc.h: `BYTES_PER_LINE 64` |
| DDR3 突发粒度 | 16B（x16 BL8） | 器件 |
| on-chip RAM | 0xF900_0000，4KB（可配更大） | soc.h |
| 外设/寄存器 | 0xF8xx_xxxx（UART/GPIO/PLIC/APB slave0 0xF810_0000） | soc.h |

> ⚠️ 我们模拟器/驱动代码里把 `DDR_BASE` 暂设为 0x8000_0000 只是 PC 模拟占位；
> **上板后 DDR 逻辑基址以你生成的 soc.h 为准（官方 demo 为 0x1000）**。所有区域应
> 写成 **"DDR_BASE + 偏移"**，改基址时只动一个宏。

## 2. 需要放进 DDR 的东西（按字节算）

| 用途 | 大小 | 说明 |
| --- | --- | --- |
| 程序镜像（.text/.rodata/.data 初值） | ≤124KB 默认；建议改到 ~1MB | bootloader 拷贝；bss/heap/栈不计入镜像但占运行区 |
| .bss + heap + FreeRTOS 任务栈 | 128~512KB | 放程序区内 |
| 精灵图/图集（引擎只读源） | ~0.5MB（游戏级可到几 MB） | 含引擎模拟模式上传的 64×64 图集 |
| 帧缓冲 0 / 1（RGB565） | 1,036,800B ×2 ≈ 2.1MB | 960×540×2B |
| 引擎/扫描行缓冲等 | BRAM 即可，不占 DDR | — |
| 可选：关卡/音频/回放 | 按需（余量巨大） | — |

## 3. 推荐的分配方案（偏移 = DDR_BASE + 值）

```
DDR 256MB（逻辑基址 DDR_BASE，官方 demo 为 0x1000）
┌──────────────────────────────────────────────────────────┐
│ 程序区    +0x0000_0000  1MB   代码/只读/数据/bss/heap/栈   │
│          (bootloader 拷贝目标；USER_SOFTWARE_SIZE=0x100000)│
├──────────────────────────────────────────────────────────┤
│ 精灵/图集 +0x0010_0000  2MB   引擎只读源（KEY 抠图源等）   │
├──────────────────────────────────────────────────────────┤
│ 帧缓冲对  +0x0030_0000  FB0  ← ★ 推荐起始地址             │
│           +0x0040_0000  FB1（间隔 1MB，双缓冲区 2MB 窗）   │
├──────────────────────────────────────────────────────────┤
│ 空闲      +0x0050_0000  ~250MB  关卡/音频/调试转储/扩展    │
└──────────────────────────────────────────────────────────┘
```

| 区域 | 偏移 | 大小 | 端地址 |
| --- | --- | --- | --- |
| 程序区 | +0x000000 | 1MB | +0x0FFFFF |
| 精灵/图集 | +0x100000 | 2MB | +0x2FFFFF |
| **FB0（Front）** | **+0x300000** | 0xFD200（≈1012KB，<1MB） | +0x3FD200 |
| **FB1（Back）** | **+0x400000** | 0xFD200（≈1012KB，<1MB） | +0x4FD200 |
| 空闲 | +0x500000 | ~250MB | +0x10000000 |

## 4. 帧缓冲起始地址为什么选 +0x300000（FB0）/ +0x400000（FB1）

1. **必须避开程序镜像区**：bootloader 把程序拷到 DDR 基址并在此运行，.bss/heap/栈
   也长在这里。FB 至少放在 `USER_SOFTWARE_SIZE`（程序区）之上——1MB 程序区 +
   2MB 精灵区之后，+0x300000 起没有任何重叠风险（即使程序镜像后来涨到 1MB、
   精灵涨到 2MB 都碰不到）；
2. **对齐**：FB0 = +0x300000 是 **1MB 对齐** → 自动满足 16B DDR 突发、**64B D$ 缓存行**、
   AXI 突发与缓存行全对齐；帧缓冲行距 1920B = 120×16B，**行首天然 16B 对齐**，
   扫描输出每行正好 120 个突发、无跨行碎块；
3. **双缓冲相隔 1MB**：FB0/FB1 各自落在完全不同的 DRAM 行/bank 区域。扫描输出
   持续"读 Front"、引擎持续"写 Back"同时进行时，行激活/预充电冲突最小；
   相隔 1MB（>> bank/行粒度）比"紧贴排放"更稳，且地址仍是整整齐齐的 1MB 边界
   （答辩好讲、脚本好验）；
4. **固定中低地址而不是堆顶**：地址全部相对 DDR_BASE 写死，引擎/扫描输出用绝对
   地址也无妨；heap 从程序区向上长，FB 在上方 4~5MB 处，即使 heap 偶发膨胀也
   有 3MB+ 缓冲——比"顶置贴 DDR 顶"更不易踩雷（顶置方案一旦算错 DDR 上限就
   直接越界）。

**备选方案**：若你担心程序镜像以后会超过 1MB，把各区域整体后移即可（程序 4MB →
FB0=+0x800000，FB1=+0x900000），原则不变：**FB 对放在"程序+资源区之后"的第一个
1MB 对齐边界，两缓冲间隔 1MB**。

## 5. 落到工程里的 4 个动作（缺一不可）

1. **bootloader**：`bootloaderConfig.h` 里 `USER_SOFTWARE_SIZE` 从 0x1F000 改到
   ≥ 程序区大小（如 0x100000），重编 bootloader.hex，并在 IPM 重新生成 SoC
   （Cache/Memory → Custom On-Chip RAM Application 指向新 hex）；
2. **链接脚本**（freertos.ld/default.ld）：`MEMORY ram ORIGIN=0x1000 LENGTH=<程序区>`
   与 USER_SOFTWARE_SIZE 一致，heap/栈在程序区内；
3. **寄存器/驱动**：`blt_regs.h` 里 FB0/FB1/SPRITE 全部写成 `DDR_BASE + 偏移`
   （DDR_BASE 用生成的 soc.h 值），引擎/扫描输出用同一组宏；
4. **验证**：用本仓库模拟器跑内存布局检查（重叠/对齐/越界断言）+ 上板后先跑
   "CPU 写 FB → 扫描输出显示"最小链路。

## 6. 两个容易翻车的点

- **缓存一致性**：CPU 开 D$（4KB/64B 行）后，**软件渲染/文本若用 CPU 直接写 FB，
  而扫描输出/引擎是 AXI 主设备直读 DDR**，可能读到缓存里的旧数据（画面不刷新/
  花屏）。对策：上板第一步验证该路径；不行就把 FB 区访问改为绕过 D$（若 SoC 支持
  区域属性）或软件写后做 cache 清洗（fence 指令 / BSP 若提供 API）；对比 demo 的
  软件路径尤其要先验证这条（模拟器不含缓存模型，无法暴露此问题）；
- **Flash 容量**：8MB Flash 里 bitstream 占约 3.5MB（demo 程序放 0x380000 之后），
  程序镜像建议 ≤1MB，别把数据也塞 Flash（精灵图运行期由 CPU 生成/从上位机载入 DDR）。
