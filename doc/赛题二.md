# 【赛题二】基于 RISC-V 与 FPGA 异构架构的 2D 图形渲染加速引擎

## 【赛题背景】

在早期的 2D 游戏机和现代嵌入式 GUI 系统中，如果完全依靠 CPU 通过死循环逐个像素搬运来实现图像的渲染，会极大占用 CPU 资源并导致帧率（FPS）骤降。现代计算架构的核心趋势是“异构计算与软硬件协同设计（HW/SW Co-design）”。

本赛题要求参赛队伍基于 RISC-V + FPGA 异构平台，设计一个定制的硬件 2D 渲染加速器。将 RISC-V 从繁重的像素搬运工作中解放出来，RISC-V 仅负责高层逻辑与下发指令，由 FPGA 硬件端完成底层像素的高速搬运与混合。

## 【任务说明】

参赛队伍需在 RISC-V 端运行游戏或图形界面逻辑，并在 FPGA 端设计一个通过标准总线（如 AXI4/Wishbone）挂载的 2D 硬件加速引擎（BitBlt Engine）。系统需能够将内存（DDR/SDRAM）中的图像数据高效搬运至显存（Framebuffer），并最终通过 VGA/HDMI 接口输出至显示器。

---

## 【基础要求】

本部分考察学生对总线协议、视频时序以及软硬接口的基础掌握能力。

### 1. 硬件 2D 位块传输（BitBlt）引擎设计

- FPGA 端需实现解析 RISC-V 发送的渲染指令（指令需包含：操作类型、源地址、目的地址、宽度、高度）。
- 硬件支持基础的“图像块拷贝（Block Copy）”和“纯色填充（Solid Fill）”。
- 生成标准 VGA/HDMI 时序，将显存内容输出至显示器（最低分辨率要求 **640×480 @ 60Hz**）。

### 2. 总线读写与存储器优化

- 加速器必须通过系统总线直接访问内存。要求合理使用突发传输（Burst Transfer）和内部 FIFO 缓存，以提高内存带宽利用率。

### 3. 软件驱动与基础 Demo

- RISC-V 端需编写 C 语言驱动程序配置寄存器，并实现双缓冲机制（Double Buffering）以避免画面撕裂（Tearing）。
- 提供一个基础测试 Demo（例如：大量方块的随机移动、多张大图的快速切换），并能在屏幕上实时对比显示“纯软件 CPU 渲染”与“硬件加速渲染”的频率差异。

---

## 【高阶挑战】

要求实现现代 2D 游戏引擎中的高级图层渲染管道。

### 1. 硬件 Alpha 混合（Hardware Alpha Blending）

- FPGA 加速器在搬运前景图层（Sprite）时，利用内部 DSP/硬件乘法器，实时读取背景像素并执行透明度混合计算：
  - 输出像素 = 前景像素 × Alpha + 背景像素 × (1 – Alpha)

### 2. 颜色键控去背（Color Keying）

- 硬件支持设定“透明色”（如纯品红色）。在搬运图像时，自动跳过透明色像素，实现不规则边缘精灵图（Sprite）的完美渲染。

### 3. 高负载互动游戏 Demo 演示

- 在 RISC-V 上运行一个具有极高同屏元素数量的游戏 Demo（如《吸血鬼幸存者》的简化版或类似《东方 Project》的弹幕射击游戏）。
- 在开启硬件加速（Alpha 混合 + Color Keying）的情况下，挑战保持 **60 FPS** 稳定运行时的同屏活动元素（Sprite）数量极限。

---

## 【技术提示（补充）】

- **总线选择**：推荐使用 AXI4 或 Wishbone 总线，注意突发传输长度与对齐。
- **显存组织**：建议采用双帧缓冲（Double Framebuffer）避免撕裂。
- **指令队列**：可设计指令 FIFO，允许 RISC-V 批量下发渲染命令，减少交互开销。
- **性能测量**：务必在 Demo 中显示实时 FPS，并对比纯软件渲染的帧率，突出硬件加速优势。
